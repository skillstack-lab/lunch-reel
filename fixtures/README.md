# Fixtures: SYNTHETIC test data (no MLB data, no video)

Everything here is generated by `tools/make_synthetic.py` (`just synthetic`). Games, players ("Synthetic Batter 7"),
headlines, playIds, timestamps and win-probability numbers are made up and deterministic; clip URLs point at
`example.invalid`. Only the JSON *shapes* mirror statsapi, so offline tests hit the same code paths as live data.
`tests/test_plan.py` checks the files match the generator byte-for-byte and contain no MLB Advanced Media content.

| path | what |
|---|---|
| `<gamePk>/content.json` | highlight items (headline, guid, date, duration, taxonomy, playbacks) |
| `<gamePk>/feed_trim.json` | play-by-play: at-bats, pitches (playId, startTime, reviewDetails), running score |
| `<gamePk>/winProbability.json` | per at-bat home-team WPA (percent) |
| `schedule/<date>.json` | schedule in `reel2.load_schedule` shape |
| `teams.json` | the 30 clubs (id, abbr, name) for `--team` lookup; same as `skills/clip-cutter/assets/teams.json` |

## Real data, locally
`just fixture <gamePk>` (or `python3 tools/make_fixture.py <gamePk>`) writes real statsapi responses to
`local-fixtures/<gamePk>/` (gitignored). That data belongs to MLB Advanced Media: use it on your machine, don't commit
or redistribute it. Then: `python3 reel2.py <gamePk> --fixtures local-fixtures --plan-only`.
